# مولّد البرومتات (نسخة الويب)

نسخة React + Vite من إضافة كروم "مولّد البرومتات"، بنفس الشكل والمنطق بالظبط.

## التشغيل محليًا

```bash
npm install
npm run dev
```

هيفتح على `http://localhost:5173`.

## البناء للنشر (Deploy)

```bash
npm run build
```

الناتج بيتحط في مجلد `dist/` — تقدر ترفعه على Vercel أو Netlify أو أي استضافة static عادية.

## الإعدادات (API Keys)

زرار الترس في أعلى الشريط الجانبي بيفتح مودال الإعدادات بدل صفحة `options.html` المنفصلة اللي كانت في الإضافة (لأن مواقع الويب مالهاش "options page"). الإعدادات وقايمة المفاتيح بتتخزن في `localStorage` بتاع المتصفح بس، زي ما كانت متخزنة في `chrome.storage.local` بالظبط — يعني نفس مستوى الخصوصية، ومفيش أي سيرفر بيشوف أي مفتاح.

### تعدد المفاتيح (Failover تلقائي)

تقدر تضيف أكتر من مفتاح Gemini من الإعدادات، وتدّي كل واحد اسم يميزه. لكل مفتاح زرار "اختبار" بيبعت طلب صغير فعلي لجوجل يتأكد إنه شغال. لما مفتاح يوصل لحد الاستخدام المجاني عند جوجل (خطأ 429)، التطبيق بيعيد نفس الطلب تلقائيًا بالمفتاح اللي بعده في القايمة من غير ما تحس بحاجة، وبيفتكر آخر مفتاح شغال عشان يبدأ منه في المرة الجاية. حدود الطلبات (أقصى طلبات/دقيقة و/يوم) في الإعدادات مشتركة بين كل المفاتيح مع بعض، مش لكل مفتاح لوحده. لو كل المفاتيح المسجلة وصلت لحدها في نفس الوقت، هتظهر رسالة واضحة بكده.

## ملاحظة أمنية مهمة

الـ API key بيتبعت من المتصفح مباشرة لجوجل (Gemini API)، ومحفوظ في localStorage بتاع كل مستخدم على جهازه. ده نفس سلوك الإضافة الأصلية، لكن لو هتنشر الموقع للعامة، أي حد بيفتح الموقع هيحط مفتاحه هو، ومفتاحه ظاهر في localStorage بتاعه (ممكن أي حد يشوفه لو فتح Developer Tools على نفس الجهاز). ده مقبول لأداة شخصية، لكن لو محتاج حماية أقوى، الحل الصح هو عمل backend بسيط يخبي المفتاح.
